# Supporting artifacts

Nothing here is cited by the manuscript. Each file either backs a single number
that the working report quotes, records a superseded stage of the audit, or is
regenerable from a script. The files the manuscript rests on stay in `UJIT/`:
`released-contradiction-verdicts-231.json`,
`false-negative-sample-350-design.json`, and
`false-negative-sample-350-screening.json`.

## Files that back a number in the report

### `legacy-contradiction-verdicts-223.json`

The pre-normalization Frame A verdicts, 223 rows over 219 unique items, all of
which the released file also carries. Keep it for one reason: it is the only
place holding the **four GPT runs separately** (`agent_1_verdict` …
`agent_4_verdict`). The released file keeps just their consensus, in
`screening_reviews[].reviewer_id = "gpt_5_6_sol_consensus"`.

That per-run detail supports the figure that the four runs disagreed with each
other on **32 of 223 items (14.3%)**, most often three against one. Without this
file, the claim that a single LLM run is not a reliable judge has no evidence
behind it in this repository.

Also carries the legacy `human_comment` field, which the normalization renamed
to `human_note`.

### `new-findings-verdicts-7.json`

Seven BIRD items adjudicated a second time by four independent channels — two
Claude Opus 5 runs and two GPT-5.6 Sol runs. All seven are also in the released
file with human verdicts, so the verdicts themselves are redundant.

What is not redundant: the panel agreed with the human verdict on **28 of 28**
judgements. Together with 217 of 218 on Frame A and 285 of 285 on Frame B, this
is the third calibration point for treating a model panel as a stand-in for
human adjudication. It is the only source of that figure.

The items are the ones carrying `EXPLICIT_TEMPORAL_RANGE_CONFLICT` (four) and
`EVIDENCE_BOOLEAN_LITERAL_MISMATCH` (three). Two of them, `bird/train/464` and
`bird/train/7074`, appear in Frame B as `FALSE_NEGATIVE_IN_SCOPE`.

## Superseded stages of the audit

### `frame-a-verdicts-224.json`

The working file that preceded the released Frame A set. It is stale in both
directions: it lacks seven rows the released set carries, and holds seven the
released set dropped after they were adjudicated `FALSE_POSITIVE+MUST_FIX`. Most
of its `human_verdict` fields are empty — the verdicts were filled in during
normalization.

Comparing a detector run against this file reports differences that are only its
staleness. `UJIT/scripts/reproduce_frame_a.py` therefore compares against the
released file and says so in a comment.

### `frame-b-screening-350.json`

The pre-normalization Frame B sample from the superseded audit. It has no
`sampling` block, so it cannot support a weighted estimate. Quantitative
checks use `UJIT/false-negative-sample-350-screening.json`.

## Regenerable output

### `reproduced-contradictions-222.json`

Output of `UJIT/scripts/reproduce_frame_a.py --dump`: the 222 contradicted items
the current code emits across all five partitions with all seven rules enabled,
each with its rule id, reason code and message. Matches the released audit
exactly — no misses, no extras — at a precision of 216/221 = 97.7%.

Kept only to save a re-run; the script reproduces it in about eighty seconds.

## Pending work

### `baseline-claim-human-queue.json`

Forty-nine items awaiting manual review: nineteen where the two adjudication
channels disagreed, plus thirty drawn at random for calibration. Filling in
`human_claim_is_a_real_problem` and `human_note` is what upgrades the baseline
comparison in the report from a model-panel estimate to a human-validated one.
Regenerated by `UJIT/scripts/finalize_claim_panel.py`.
