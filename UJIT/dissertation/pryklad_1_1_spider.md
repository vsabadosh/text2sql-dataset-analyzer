# Приклад для пункту 1.1.1

Робоча трійка для формалізації задачі Text-to-SQL. Замінює ілюстрацію з Mohammadjafari, Maida, Gottumukkala (arXiv:2410.01066, https://arxiv.org/pdf/2410.01066v1): у них питання про заправки не збігається зі згенерованим SQL.

Огляд цитується лише за етапи: питання, схема, прив’язка фраз до таблиць і колонок, генерація SQL, виконання. Рисунок з їхньої статті не перемальовувати.

Речення «What are the names of singers older than 30?» у корпусі Spider немає. Це навчальний приклад на справжній схемі бази `concert_singer` (Spider 1.0, Yu et al., 2018), а не золотий пункт корпусу.

## Трійка

Питання: What are the names of singers older than 30?

Українською на рисунку: «Як звати співаків, старших за 30 років?»

Рисунок: [pryklad_1_1_spider.svg](pryklad_1_1_spider.svg)

Схема, фрагмент бази `concert_singer`, таблиця `singer`:

| Колонка | Тип |
| --- | --- |
| Singer_ID | number, первинний ключ |
| Name | text |
| Country | text |
| Song_Name | text |
| Song_release_year | text |
| Age | number |
| Is_male | others |

SQL, що відповідає питанню:

```sql
SELECT name FROM singer WHERE age > 30
```

## Зв’язування зі схемою

| Фраза питання | Що це в SQL |
| --- | --- |
| names / як звати | колонка `name` |
| singers / співаків | таблиця `singer` |
| older / старших … років | колонка `age` і оператор `>` |
| 30 | літерал, не колонка |

Число 30 лишається константою у `WHERE`. Саме тут ламається приклад із заправками: фразу «2 miles» там цілком прив’язано до колонки `Distance`.
